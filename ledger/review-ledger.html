How the numbers are made. Each run is written by the review skill when it finishes; nothing here is edited by hand.
review time
per run: from the "review started" comment on the ticket to the findings being posted (or the blocked comment); per ticket: every run on it added up
iteration
the run's position among all runs on the same ticket, oldest first
time to PASS
first run started → the PASS run finished; "open" until a PASS exists
complexity
size of the diff, not the review: lines (<100 = 1, <400 = 2, <1000 = 3, else 4) + files (≥3 +1, ≥10 +2) + more than one module (+1) + Bug type (+1). Low ≤ 2, Medium 3–4, High ≥ 5. Blocked runs have no diff and no score.
outcome
qa handoff · rework (sent back) · posted (findings only) · report only · blocked (branch or PR missing)
project
the product name from each repository's jira-project.json, else its Jira project key; one ledger serves every repository that reports to it
